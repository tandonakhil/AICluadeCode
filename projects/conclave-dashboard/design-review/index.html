    Screen 5

    Encoding legend — the component sheet

    Published on the product itself. A derivation the reader cannot inspect is one they cannot distrust.

    Layer 1 · attention index (4 states)

    ● RED approval never asked · gate skipped without exception · recorded endpoint down
    ▲ AMBER gate ran incompletely · open loop-back · degraded runtime · stale source · coverage gap
    ? UNKNOWN any input unreadable, any probe inconclusive, any chip that cannot enumerate its reasons
    ✓ GREEN every gate closed, every approval given, runtime up, all sources fresh — an intersection
    Red and amber are unions — any one finding trips them. Green is an intersection — everything must hold. Precedence: RED → UNKNOWN → AMBER → GREEN.

    Layer 2 · gate states (from admin/PIPELINE.md §3)

    ✅doneclosed, human approved
    ▶activecurrently running
    ↩loopedfailed and sent work back
    ⚠warnran, but incompletely
    ⬜pendingnot started

    The three flavours of ⊘ — three marks, never one

    ⊘n/a not applicable — by template. Dashed. No approval was owed.
    ⊘pre-gate the gate did not exist — hatched. A real coverage gap.
    ⊘skipped skipped without an exception — solid red. Second-loudest thing the page can render.
    These three rendered identically for weeks. That is how a skipped Review gate stayed invisible. Distinguishing them is not a nicety; it is the requirement.

    Approval states (5)

    ✋ approvedthe human approved
    ✋ YOU approve?waiting on you right now — loudest element in the system
    ✋ —not reached yet
    ✋ n/agate not applicable, no approval owed
    ✋ NOT ASKEDan approval was owed and never requested

    Type — provenance made typographic

    mono 12.5 anything the machine produced: IDs, paths, timestamps, glyphs, states
    sans 13.5 anything a human wrote: callout titles, ledger notes
    32/600 KPI numerals — tabular, weight 600. Not 200-weight ultralight: a hairline 5rem numeral is the least legible element on most dashboards.
    Section mono 11 · 0.28em · leading rule — kept verbatim from The Signal Path

    Reconcile / supersede — The Signal Path

    KEPT void/floor/surface scaffolding · hairlines · mono eyebrow + rule · aperture slit as the gate motif · tabular-nums · grain at 0.03
    SUPERSEDED dark-only — the canonical classDef palette is a light palette; a dark-only surface cannot host the verbatim graph honestly
    SUPERSEDED theatrical display type — a status report is dense by requirement; the "≥1 element over 3rem" test is explicitly waived for /status
    SUPERSEDED ambient animation — motion connotes liveness. A permanently animated status page asserts "live" every frame, including when the data is 18 days stale. Nothing loops, nothing idles.
    SUPERSEDED ember accent — #f5a83c sits on top of the canonical warn amber. Status hues are reserved for status; the accent is reserved for navigation, selection and focus. Never crossed.
    Accessibility acceptance test. Print any screen greyscale: no fact may be lost. Every state carries a glyph and a word; colour only intensifies a distinction already legible in monochrome. No fact is reachable by hover alone — which also means every fact survives a screenshot, and screenshots are how this platform records test evidence.

    Same state, different control. Rendered so the choice can be judged rather than argued.

    conclave/status

    Four other projects are ● RED right now. You cannot tell from this screen. The control's job is to hide the options.

    conclave/status

    Same switch, one click, and every other project's state is on screen while you read this one. Degrades to the <select> above ~8 projects, where the rail's advantages invert and R1's original instinct becomes correct.

    My recommendation, stated as disagreement rather than compliance. R1 asks for a dropdown; I am proposing the rail plus a portfolio landing view. The intent of R1 — "switch projects, not five stacked graphs" — is fully met, and better met, because the portfolio view contains no graph at all. My objection to the literal dropdown is narrow and specific: a closed dropdown cannot carry state, so while you read one project, a red one is invisible by design — the same class of failure as the ⊘ conflation. If you prefer the dropdown, it drops straight in; the two are the same state differently rendered. The one thing I would push back hard on is a dropdown without an always-visible portfolio row, because that puts the bad news one interaction away.
