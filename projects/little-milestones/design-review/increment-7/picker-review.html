Increment 7 — F17 Picker hand-off + import review

Three-step sequence between "Import photos" (Settings, connected state) and the actual import: (1) an app-styled intro sheet/dialog priming the hand-off, (2) Google's own Picker widget (out of this app's visual control, launched via Google's Picker API), (3) this app's own review- before-import step once the picker closes and control returns.

2. Google's own Picker widget — genuinely new component vocabulary, flagged below

Not a reused component — flagged explicitly, not silently fit into an existing pattern. This is the one surface in the entire app where a foreign visual language legitimately appears: Google's Picker API opens its own native UI (typically a browser popup/overlay) to let the caregiver browse and select from their Google Photos library. This app does not, and by design should not, build its own library-browsing view for someone else's photo library — that would mean handling library-wide access this app deliberately doesn't request (scope minimization, FEATURES.md F17). The mockup below is a labeled approximation of that widget's shape (native-looking selection tiles, Google's own "Select" action), not a component this app owns, styles, or can theme with --lm-* tokens. code-agent/Architecture should treat it as a black box this app launches and receives a result from — no visual spec is being handed off here because there is nothing to specify beyond the two mockups on either side of it.

Duplicate detection: a photo whose imported bytes appear to match one already stored for the target child (content-hash comparison at import time — exact mechanism is Architecture's to specify) shows a slate "Looks like a duplicate" badge (reusing the non-alarm slate information-surface convention, §1.3/UXR-2 — never terracotta/danger, since this is informational, not an error) with a per-photo skip toggle (✕, defaults to skipped so a caregiver doesn't accidentally double- import, fully overridable with one tap). Child selector: a compact row reusing the existing identity-dot + name pattern from the switcher, tapping it opens the standard child-switcher sheet already shipped app-wide — no new picker component for this. Confirm button copy updates its count live as photos are skipped/toggled, and is disabled when the count reaches zero (never a silent no-op). Photogrid reuses AddMemoryForm's exact 3→5 column, 768px-breakpoint precedent (§5.6) — no new grid convention.
