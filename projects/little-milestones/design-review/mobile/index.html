Release 1 scope — the honest cut

The web product exposes roughly 40 endpoints. Release 1 of the mobile app deliberately ports the journey a parent actually performs on a phone, one-handed, in interstitial moments — and defers everything that is genuinely better on a bigger screen with a keyboard.

In release 1Why
Sign in / sign up / join-by-invite, TOTP, sign outNon-negotiable entry. Password reset deep-links to web.
Child switcher, add a child, corrected ageMulti-child and preterm handling are core, not advanced.
Today — activities, coming-next, this-week, ideasThe daily re-open reason.
Ask — chat, suggested prompts, history, delete sessionThe 2am reason.
Journey — timeline, gallery, lightboxThe retention core, and the best thing about having it on a phone.
Capture — camera, library picker, text-only memory, offline queueThe one thing mobile does that web cannot.
You — profile, caregivers list, digest toggle, security, deleteConsent and deletion must never be web-only.
DeferredWhy
Google Photos import (F17)A browser-redirect OAuth flow plus a third-party picker plus an import-review table — the single least phone-shaped surface in the product, and the one with the most compliance surface to re-verify on a new platform. Web link in the You tab.
Caregiver invite creationViewing caregivers ships; generating an invite code ships in release 2. Rare, one-time, and a code is easier to hand off from a desktop.
Password reset, TOTP enrolment, session revoke UIReset is an emailed browser link already; TOTP enrolment needs a QR on a second screen. Login with TOTP ships.
Push notificationsNot designed here at all. A parenting app that pushes about development is an anxiety machine unless designed carefully — that deserves its own gate, not a checkbox.
Full offline read of the whole journeyRelease 1 caches what was recently viewed. A complete local mirror of every child photo is a privacy decision, not a caching decision.

1 · Cold start & navigation architecture

Launch → session restore → sign in → optional app lock → child selected. Bottom tabs (Today · Ask · [+] · Journey · You), each owning a native stack; child switching is a header-chip sheet on every tab, never a tab of its own.

2 · Today tab

Loaded, loading (skeletons), error/stale-cache, and empty states.

3 · Ask tab — chat

First-open, keyboard-up with streaming, history sheet, and offline with a queued question. The keyboard-avoidance contract is stated on the page.

4 · Journey tab

Timeline river, gallery grid, native lightbox with swipe/pinch, and the empty state. UXR-1 (no norm axis, no comparison) re-verified for every one of them.

5 · Capture — the centre [+] action

Capture sheet → permission pre-prompt → compose → optimistic save with offline queue. Four privacy decisions are flagged on this page for security-architect.

6 · You tab, 2am mode, accessibility & system states

Account surface; the warm-dark night theme; dynamic type at ~130%; the app-switcher privacy blur; hard-offline cold start; and the accessibility contract the Test gate will assert against.

What this pass does not cover, stated rather than implied: tablet/iPad layouts (phone-first only; the app runs on tablet at phone metrics in release 1), landscape beyond the lightbox, push notifications, deep-link/universal-link routing, an onboarding flow for a brand-new account on mobile (release 1 assumes an account created on web or the existing web onboarding copy reused verbatim in a native stack — the copy is unchanged either way, §1.10 is binding), and app-store assets.
