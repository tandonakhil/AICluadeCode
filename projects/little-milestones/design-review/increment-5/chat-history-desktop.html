Increment 5 — Chat History Browsing (desktop, ≥1024px), F13 part 1

Mobile uses an icon-triggered bottom sheet (see chat-history-mobile.html); desktop has real horizontal space, so history gets its own persistent 230px rail — visible only on the Chat screen, sitting between the existing 248px-class nav sidebar and the 640px-capped chat column (§5.3). This deliberately does not fold history into the main nav sidebar, which §5.1 explicitly scopes to "nav + identity, nothing else" — adding a per-screen browsing list there would violate that existing, reviewed constraint. Chat's own reading column keeps its 640px cap unchanged; the rail uses space the sidebar/margin design already reserved as "decorative wash" (§5.3) for a surface that, on Chat specifically, now has real content to put there.

Note on this desktop-only structural addition

This is the one place this pass adds new desktop layout surface beyond what §5's existing responsive system specifies (sidebar nav, 640/680px reading columns, 2-col Today grid). It's scoped tightly: visible only on the Chat route, uses the app's existing hover/active-state and card-tint conventions rather than inventing new ones, and does not change the chat column's own width or content. Same accessibility bar as everywhere else in this KB applies (UXR-6): rail rows are a real <nav>/<ul> of focusable, keyboard-reachable buttons with visible focus rings, not a mouse-only affordance — the delete button's hover-reveal on desktop must also appear on keyboard focus (:focus-within), not hover alone.
