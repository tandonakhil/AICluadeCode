2 · Desktop width — validated screen by screen

Verdict summary: the human is right about Ask and Today (Ask is actually a shipped layout bug — the §9.1 history rail was designed to sit outside the 680px chat column, but the shipped CSS squeezes rail + chat into the generic 640px cap). Journey gets a modest widen at very large screens only. Settings and the chat bubble column stay capped, deliberately — reasoning below, per screen.

Ask — AGREE, and it's a bug: 640px → 930px at ≥1024px. No .lm-content[data-screen="chat"] override exists, so the generic 640px cap applies and the 230px history rail + 20px gap leave only ~390px for the conversation — narrower than a phone. UX_KB §9.1 specified rail beside a 680px chat column. Fix: .lm-content[data-screen="chat"]{max-width:930px} (230 rail + 20 gap + 680 chat). The bubble column itself stays capped at 680px — 1000px-wide chat bubbles hurt line-length readability and drift toward a support-console register (§5.3's reasoning stands).

The Gallery view inherits the same cap (5-col tiles grow ~145px → ~166px). This is deliberately the smallest change on this page.

Settings — KEEP 680px, explicitly. A single-column account/form screen (family list, invite code, digest toggle, profile photo) has no card collection that benefits from width — the Increment-3 fix pass already made this a recorded, deliberate decision, and §5.2's onboarding reasoning (wider forms only lengthen eye-travel per line) applies verbatim. Honest disagreement with a blanket "use more screen everywhere": widening Settings would add emptiness, not utility.
What deliberately does NOT change anywhere: chat bubble column ≤680px (readability), the sidebar's nav-and-identity-only role (§5.1 — no dashboard widgets in reclaimed space), single-column mobile layouts, and every R1/UXR rule. Extra desktop width is spent on breathing room and honest density where card collections exist, never on new information panels.
