Photo Personalization (revision 4) NEW

Human feedback: "once a parent uploads their kid's pics we should show pictures in general theme so it looks personal. if no picture then default theme." This section shows a decorative photo-derived accent layer applied to select surfaces (hero gradients, card accent borders, background wash, switcher avatar ring), the same screen in the unmodified default theme for direct contrast, and the child switcher previewing two independent per-child accents. Full design rationale, the AA-contrast guarantee for arbitrary photos, and the hard exclusion of the slate/red/text tokens are in UX_KB.md §6.

Personalized: hero/header gradients, card accent borders, top background wash, child-switcher avatar ring.   Never personalized: the slate pediatrician-note surface (R1/R2), the single red destructive color, all body/UI text and its contrast ratios, primary action color (terracotta stays the one tappable-affordance color everywhere).   AA guarantee: extracted accents are clamped to safe lightness/saturation bands, a fixed-opacity dark scrim (independent of hue) sits behind any white headline text, and an automated pre-render contrast check falls back to the default theme for that surface if a fixture photo would still fail — personalization degrades to default, never to a contrast violation.   Default state: no photo = the complete, unmodified rev-2 theme, not a gray placeholder.   Multi-child: each profile's accent is derived from its own photo only — never shared across children.
