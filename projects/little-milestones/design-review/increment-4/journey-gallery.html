Tapping any tile here opens the exact same <Lightbox> component shown open in journey-lightbox.html (F15) — the only difference is the photo list it's seeded with: the timeline's trigger scopes prev/next to one memory's own photos, this gallery's trigger scopes prev/next to every photo on the profile, in the same chronological order the grid itself is laid out in.
Implementation note for code-agent (design spec, not code) —
  • Toggle placement: a new .lm-view-toggle segmented control sits between the existing "+ Add a moment" button (position unchanged) and the content it switches — river or grid, never both. Default view: Timeline (unchanged first-open experience); the choice is client-only useState for this pass, not persisted server-side per user — a scoped simplification, flagged here rather than silently decided.
  • Content model: the gallery flattens every photo_ids entry across every timeline memory (already fetched by getTimeline, no new API call) into one chronological list — same order the river already presents them in. No date/age labels or hover overlays on tiles (UXR-1: a dense grid of bare photos carries no norm axis, no comparison framing, same discipline as the river's own chapter-marker-only labeling).
  • Grid: 3 columns mobile, 5 columns ≥1024px — reuses the exact column-count precedent already established by .lm-photogrid in the add-memory sheet (3 → 5 at its own 768px step), applied here at the app's one shared 1024px breakpoint instead, since Journey's other desktop treatment already keys off 1024px.
  • Empty state: if the profile has memories but none with photos yet, the Gallery view shows its own calm empty message ("No photos yet — add a moment with a photo to see it here.") rather than an empty grid; Timeline's own separate empty-state message is unaffected.
  • Accessibility: the grid is a plain <ul> of <button>-wrapped images (native tab order, no custom grid-arrow-key navigation needed for this pass); each tile's aria-label carries the parent memory's title so a screen-reader user gets the same context a sighted user gets from the river's card text.
