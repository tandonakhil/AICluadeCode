Enrolled-state differences from state 1, named explicitly: the status chip flips to the sage "On" treatment (an existing non-alarm confirmation color, §1.3 — never gamified green-means-good semantics, just the same sage already used for supervision lines); the CTA becomes lm-btn-quiet "Turn off" rather than a prominent secondary button, since disabling MFA is not an action to visually encourage; and a one-line status ("Turned on {date}. {n} recovery codes remaining") replaces the not-enrolled description, giving the caregiver a passive signal of how many codes are left without a separate screen.

6 — Change-password inline form (expands under the Security card's "Password" row)

Security

Password

Per SECURITY_KB §7.4, an authenticated change-password keeps the current session alive (only OTHER sessions are ended) — deliberately different from the reset flow's delete-all, since a logged-in, password-knowing change is not a compromise signal. No UI difference is needed to convey this; it's a backend behavior, noted here so the distinction isn't lost between this file and code-agent's build.
