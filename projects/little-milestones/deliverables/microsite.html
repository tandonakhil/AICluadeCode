What it is

little-milestones answers a single recurring question — what is normal for my child right now? — without ever telling a parent their child is behind. Age is computed server-side from date of birth at query time, including corrected age for children born preterm, and every piece of content is conditioned on that number. The LLM never computes an age and never originates a milestone claim.

Age-aware milestone chat

Conditioned on the selected child's computed age, framed on the CDC-2022 75th-percentile standard: “most children do X by Y”. Hard medical-question deflection; red-flag concerns are always routed to a pediatrician and never minimised.

Corrected age, done properly

Preterm children get corrected age through 24 months, with defined behaviour for newborns and for children over 36 months instead of extrapolation. Corrected age is never used to explain away a regression.

A life-journey timeline

Parent-logged moments with photos, rendered as a story. A hard visual rule: never an expected-vs-actual axis, never a typical-range band. Checklist ages appear only as neutral chapter markers.

Activities and what's coming next

Stage-appropriate activities with supervision context, filtered by hard safety rules, plus a short preview of the next stage — the category's strongest re-open trigger.

Multi-caregiver families

Invite a second parent or a grandparent. Caregivers view and log; only the owner can delete a child profile or photos. Cross-family access returns 404, not 403.

On the phone, at 2am

The native app is designed around the actual use case: one-handed, camera-in-hand, frequently interrupted. Every primary action sits in the bottom third of the screen.

Who it is for

Parents and caregivers of children from birth to about three years — disproportionately first-time parents, and parents of preterm children, for whom generic milestone content is actively misleading. Multi-caregiver support means grandparents and second parents are first-class users, not an afterthought.

Market position

The industry read places this in consumer parenting / family tech — BabyCenter, Huckleberry, Wonder Weeks, Qeepsake territory. It is explicitly not a healthcare or pediatrics product and makes no clinical claims.

  • AI has to earn its keepThe 2026 field has moved past generic chatbots toward AI that anticipates the child's stage. An age-aware chat only matches the market if answers genuinely change as the child ages.
  • Credibility next to a free government appThe CDC Milestone Tracker anchors parents' expectations. Commercial apps survive by clearly framing suggestions as parenting ideas rather than developmental screening — and saying so.
  • Memory-keeping is the retention engineQeepsake and Lifecake built businesses on low-friction journaling and timelines. Photos plus timeline is not a nice-to-have in this category; it is the emotional core that keeps parents for years, where sleep trackers get abandoned once sleep stabilises.

The trust posture, which is the product

Data minimisation by design. No last name, no gender, no demographics beyond date of birth and prematurity status. Photos are encrypted at rest, EXIF-stripped, served only through authenticated family-scoped routes and never a static mount. There is no face detection of any kind, and the photo pipeline has structurally no code path into the LLM layer — child photos cannot be used for AI training because there is nowhere for them to go. Delete actually purges the file bytes, and there are deliberately no automatic backups, because a backup is a second copy of child data that would contradict the deletion promise.

A plain-language non-medical disclaimer is carried in every chat and activities response payload, not just painted in the UI — so the test suite can assert it on every response rather than trusting that it is there.

One backend, three surfaces

Since 26 July 2026 the product ships on three surfaces sharing a single FastAPI backend. The mobile client was added without forking the credential model: the same opaque session token is simply accepted from a second transport.

Its component map still describes a backend plus a Next.js frontend only. The mobile architecture is fully designed — it just lives in SECURITY_KB.md §9 and UX_KB.md §13 instead. Component by component

ComponentWhat it is
Next.js desktop webThe original and still primary surface, on :3000. Authenticates with an HttpOnly, SameSite=Lax session cookie. Its behaviour is byte-for-byte unchanged by the mobile work — a hard constraint on that design, not an aspiration.
React Native / Expo mobileExpo SDK 57 on react-native 0.86. Bottom tabs with each tab owning its own native stack, plus a central [+] capture action that is deliberately not a tab. Child switching is a header chip, so it never costs a tab slot and never costs a parent their place in the app.
expo-secure-storeiOS Keychain / Android Keystore, with WHEN_UNLOCKED_THIS_DEVICE_ONLY. AsyncStorage is prohibited for the session token: it is unencrypted in the app sandbox and included in default device backups, which would leave a 30-day children's-data credential in cleartext in a desktop backup folder.
auth.py · _extract_raw_token The single new read path. Returns the session cookie if present; otherwise parses Authorization: Bearer. The cookie is checked first and wins on conflict — that ordering is what structurally guarantees no browser request's resolution behaviour can change.
sessions tableOne token type for both surfaces: same SHA-256-at-rest hashing, same 30-day sliding / 90-day absolute expiry, same mfa_pending semantics, same revocation surface. A sessions.client column records web or mobile so the “log out everywhere” screen can name the device being revoked.
ages.pyPure age math: completed months, CDC checklist bucketing, corrected age for preterm children through 24 months, and defined behaviour outside that range. Server-side only — the LLM never computes an age.
prompts.py + curated JSONA hand-curated CDC-2022 milestone table is injected into the system prompt as a grounding block. Model weights mix pre-2022 50th-percentile and post-2022 75th-percentile framings indiscriminately, and no amount of prompting reliably fixes that, because the model does not know its source is stale.
guardrails.pyOutput-side enforcement, backstopping the system prompt rather than trusting it. Instructions are not a control.
crypto.py + photo storePhoto bytes live encrypted on the filesystem, not in SQLite; metadata rows carry the IV, never the key. Delete unlinks the file, so deletion is literal.
SQLiteA single file with PRAGMA foreign_keys = ON and ON DELETE CASCADE, which turns hand-rolled cascade logic into database-enforced invariants that cannot drift between store implementations.

Why bearer, and what was rejected

  • Let React Native carry cookies — rejectedIt almost works, which is precisely why it is dangerous. The platform cookie jar is undocumented-by-contract, differs between Expo Go and release builds, and is unencrypted and inside the default backup set. HttpOnly also buys nothing on a client with no DOM.
  • A separate mobile token type — rejected as gold-platingIt would fork the credential model in two: two lifetimes, two revocation paths, two places for mfa_pending to be wrong.
  • Full OAuth2 / PKCE — rejectedA first-party app talking to its own first-party backend has no third party to delegate to. It would mean standing up an authorization server to issue tokens to ourselves.

Mobile clients are deliberately sent no Set-Cookie — a cookie would recreate the rejected design by accident — and receive the token in an X-LM-Session-Token response header, which must never be added to CORS expose_headers.

How this was actually built

little-milestones was built by Conclave, a multi-agent SDLC system: a roster of specialist agents convened per project, deliberating under one orchestrator, with the human holding final say at every gate. What follows is this project's real history — not a description of how the system works in general.
