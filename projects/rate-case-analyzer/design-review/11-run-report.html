What you are looking at

The second surface. The ingestion job ships and fails independently of the web app, and its only observable output is this report plus an exit code. The spec does not require it to be a web page — it requires a human-readable report and a machine-readable structured form. This is the human-readable half, given the same visual language as the rest of the product so the two surfaces are recognisably one system.

  • Quarantine is reported as a complete table with explicit zeros (AC-F43-03). Every reason in the closed set is listed on every run, including the ones that did not fire. A section that disappears when its count is zero is the same failure as an empty flag list on the answer screen: you cannot tell "none" from "not checked".
  • Confidential material is quarantined and reported, never flagged and indexed. The evidence that triggered it — the actual marking text — is quoted, because that is what lets a human confirm the classifier was right without reopening the document.
  • Extraction gaps are a separate list from quarantine. A parse failure is a third state: no claim row is written, nothing is quarantined, and the document is in the corpus. This list is the only place that fact is recorded, and it is what screen 05's right-hand column points at.
  • The silent-stop health check is on the report, not only in a log. A job that has stopped running produces no report at all — so the check is against the clock, and it is visible from the last report that does exist.

Why this one is red and the PARTIAL run is not

A quarantine is the pipeline correctly refusing a document.
