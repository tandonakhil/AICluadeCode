What you are looking at

The ingestion job is the product's second surface, and it fails independently of the web app. A silently-stopped scraper yields a stale corpus, and a stale corpus yields confident, wrong, well-cited answers with no UI symptom at all — unless this banner exists. It is therefore in the app bar on every screen including the empty first-run screen, not tucked into a settings page.

Four states below. Note that a failed run never advances the as-of date (AC-F39-05, amended per ASM-26) — the banner reports the last SUCCEEDED-or-PARTIAL run, and mentions a newer failed one separately. A PARTIAL run (expected quarantines, still exit 0) does advance it: gating on SUCCEEDED alone made the corpus permanently undateable, since a real corpus quarantines something on nearly every run. And the date in this banner is always the same date shown on the coverage panel (AC-F39-06) — one fact, one value, two places.

State 1 · Fresh — a successful run inside the threshold

Rate Case Analyzer precedent research

Session: Utility analyst · public + internal corpora
Corpus as of 7 Aug 2026, 03:12 UTC · last ingest run succeeded

Quiet by design. Filled dot, neutral surface, no adjective. The date is still stated in full rather than as "today" — an analyst copying a figure into filed material needs the actual as-of date, not a relative one.

State 2 · Stale — the last successful run is older than the 30-day threshold

Rate Case Analyzer precedent research

Session: Utility analyst · public + internal corpora
Corpus as of 2 Jun 2026, 03:09 UTC · 66 days old — no successful ingest run since

Amber, and it states the age in days rather than only the date, because "2 June" does not compute to "over two months" at a glance mid-task. The age is the finding. Colour is redundant here: remove it and the words "66 days old — no successful ingest run since" still carry the whole message.

State 3 · A newer run did not succeed

Rate Case Analyzer precedent research

Session: Utility analyst · public + internal corpora
Corpus as of 28 Jul 2026, 03:11 UTC · the run of 7 Aug 2026 did not complete — the as-of date has not advanced

The date shown is the last successful run. The unsuccessful newer run is mentioned, never substituted — a partial run that ingested half the new filings must not be allowed to advertise itself as current coverage. Detail belongs in the run report, linked from here.

State 4 · No ingest run has ever succeeded

Session: Utility analyst · public + internal corpora
No ingest run has ever succeeded — this corpus cannot be dated

Dashed and hatched, so it does not read as a date at all. This state is load-bearing: the surface never answers over a corpus it cannot date, so a question asked in this state is refused, naming that as the gap. The refusal is below.

No ingest run has ever completed successfully, so there is no dated corpus to answer from. Anything returned now would carry an as-of date the system cannot vouch for.
