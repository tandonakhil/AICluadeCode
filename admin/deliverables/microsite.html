What Conclave is

Source: CLAUDE.md, admin/MAS_REGISTRY.md

The pitch

Conclave is a Multi-Agent System that builds and operates a portfolio of AI-centric applications for the energy industry — GenAI chatbots, agentic workflows, RAG/knowledge-base apps — through a gated, human-in-the-loop SDLC pipeline, not an unsupervised autonomous builder. A roster of specialist agents is convened per project, deliberating under one orchestrator, with the human always holding final say at every gate.

Governed, not autonomous Human approves every gate

Who it serves

Teams building AI-centric applications for the energy industry who need real engineering discipline — architecture review, security review, test coverage, human sign-off — without hand-rolling that process for every new project. Conclave supplies the specialist roster and the gate structure; the human supplies judgment and final approval at each step.

Two axes, never mixed

/new-project, /enhance-project, /modify-feature, /consult build and evolve individual applications. /admin-panel evolves Conclave itself — never reachable from a project command, never touches projects/.

The value proposition

Every project gets the same disciplined pipeline — Plan, Architecture, Code, Test, Review, Deploy — with the right specialist SMEs convened for its actual risk profile, and a human who never loses the ability to stop, redirect, or override at any gate.

Sequencing discipline

Every deferred item follows the same rule: prove the simple case first, build the harder version only once a real need surfaces — applied consistently (usage-monitor tracking before auto-pause/resume, conflict detection before automated resolution, feature flags deferred until a release actually needs surgical rollback).

How Conclave governs and extends itself

Source: CLAUDE.md, admin/MAS_REGISTRY.md. Conclave builds itself using the same governed process it applies to every project — self-hosting its own discipline.

Real precedent: how deliverables-agent and synthetic-data-agent got built

mas-architect gave advisory review of each proposed role (checking for overlap with existing agents, deciding core-vs-optional status and gate placement) — purely advisory, never self-approving. The human reviewed and approved each recommendation explicitly before mas-registrar scaffolded the actual agent file and updated admin/MAS_REGISTRY.md. synthetic-data-agent's full path: proposed 2026-07-11 from a real concrete need, advisory-reviewed, human-approved via checkbox roadmap review 2026-07-12, then built — no step skipped.

The same discipline, at every scale

Whether a human is approving one project's Architecture gate or approving a new agent's addition to the platform's own roster, the shape is identical: an agent (or a small roster of them) proposes, the orchestrator surfaces it clearly, and only the human's explicit approval moves it forward. Conclave never grants itself permission to change its own roster — the same rule it enforces on every project it builds.
